# Steps
1. Verify before writing: run or read the actual install/build commands, check the real CLI flags, config keys and API signatures. Never document something you have not confirmed.
2. README structure (adapt to the project):
   - Name + one-sentence description of what it does and for whom.
   - Quick start: prerequisites with versions, install, the minimal working example.
   - Usage: the common tasks with copy-pasteable commands/code.
   - Configuration: options, env vars, defaults.
   - Development: build, test, project layout, how to contribute.
   - License.
3. Style: short sentences, active voice, code blocks with language tags, real examples over abstract descriptions. Update docs in the same change as the code they describe.
